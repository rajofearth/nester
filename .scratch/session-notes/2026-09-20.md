## Bugs found in live testing (queue for next session, roughly by priority)

1. **Entries screen is a flat path list, not a gallery.** The product says
   "native gallery, not a file manager". Need the three-view model: Photos/Videos/Files
   tabs (media grid + file list), replacing the raw path rows. Research points:
   Paging 3 + LazyGrid, stable keys, fixed aspect-ratio cells, Coil singleton.
   This is the big one. See ticket 12 (create it).
2. **Folders screen shows `\\?\C:\Users\Yashraj\Pictures`** - Win32 extended-length
   prefix from canonicalize() leaks into display. Fix display-only: keep the canonical
   path for IO + folder_id (changing both would invalidate folder ids -> phone
   re-books everything), strip `\\?\` only for what goes into the API/GUI.
3. **`.nester-tmp` (host's upload temp dir) shows as a folder in entries.** Hide it
   server-side (entries query + scan should skip that dir name inside the root).
4. **Camera backup "Backed up 0 of 1976" tally** counts every failure into "sent" bytes;
   the bar full at 1/1976 after a failed run was that. Cosmetic once uploads succeed,
   but the end-state readout should say "0 of 1976 · failed" not "1/1976, full bar".
5. Row height on entries: per-row Download/Open+Delete buttons make rows ~160px tall;
   collapse into overflow menu or long-press actions once the gallery view lands.

## Research conclusions already banked (in .scratch/ + reports below were verbal)

- Sync-state vocabulary: 6 states max, per-folder primary, global summary in header +
  tray; "Waiting for phone" folds all peer-offline cases; never show a green "up to
  date" when the peer is gone.
- Desktop: tray = single source of truth; close = hide; errors as counts linking to a
  list with per-file cause and auto-retry (Syncthing model). Done for the surfaces that
  exist; error-count plumbing per folder is next when failures are real.
- Desktop OS: autostart via HKCU Run (done); NSIS/Inno installer + firewall rule
  (elevated, scoped to localsubnet/private profile) when we want install-time
  provisioning; until then the portable exe + in-app toggle + firewall prompt is fine.
- Android: WorkManager (ticket 11) for background auto-backup + share target;
  no foreground service (Android 15 dataSync 6h budget); battery optimization
  deep-link, not direct request; OEM killers -> "backup stalled" banner instead.
- Correctness: trust mtime+size only within the 2s window; validate paths host-side;
  clock-skew check (phone vs host Date header, warn if > 60s) is a cheap future add.
- Gallery performance checklist when we build ticket 12: Paging 3, aspectRatio(1f),
  keys, contentType, no SubcomposeAsyncImage, memoryCache ~30%.
- Video-only Range resume with If-Range/strong ETag (server already sets mtimes).
